# 志愿者智能调度平台 — 微信小程序开发文档

---

## 1. 小程序建设范围

小程序 `miniapp` 面向 **志愿者/安保人员**，用于完成注册认证、活动报名、排班查看、现场签到、定位上报、通知查看、收入查看等移动端操作。

管理后台 `frontend-admin` 面向活动主办方和现场管理员，不在本文范围内。

---

## 2. 技术栈

| 类型 | 选型 | 说明 |
|------|------|------|
| 框架 | 微信小程序原生 / uni-app | 推荐优先 uni-app，方便后续多端扩展 |
| 语言 | TypeScript | 类型约束 |
| UI 组件 | uni-ui / Wot Design Uni | 表单、列表、弹窗、日历 |
| 状态管理 | Pinia / 简单 Store | 用户信息、Token、活动状态 |
| 请求库 | 封装 `uni.request` | 统一 Token、错误处理 |
| 地图 | 腾讯位置服务 / 微信地图组件 | 定位、签到、附近区域 |
| 构建工具 | Vite / HBuilderX | 视技术选型确定 |

## 4. 页面模块

### 4.1 登录/注册

| 功能 | 说明 |
|------|------|
| 微信授权登录 | 获取微信用户身份 |
| 手机号绑定 | 绑定平台账号 |
| 志愿者注册 | 填写姓名、手机号、身份信息 |
| Token 保存 | 登录后保存 Token |

当前后端登录认证接口还未完整，前端先预留登录、Token、用户信息模型。

### 4.2 首页

展示：

- 当前活动
- 今日排班
- 签到状态
- 未读通知
- 收入概览

快捷入口：

- 活动报名
- 我的排班
- 扫码签到
- 我的通知
- 我的收入

### 4.3 活动列表与报名

页面：

- 活动列表
- 活动详情
- 岗位列表
- 报名确认

功能：

| 功能 | 后端接口 |
|------|----------|
| 活动列表 | `GET /activity/page` |
| 岗位列表 | `GET /position/list` |
| 岗位详情 | `GET /position/{id}` |

> 当前后端报名接口还需补齐，小程序先按“选择活动 + 岗位 + 可服务时间”的交互设计。

### 4.4 我的资料

页面：

- 基础资料
- 实名认证
- 技能标签
- 可服务时间

功能：

| 功能 | 后端接口 |
|------|----------|
| 注册 | `POST /user/register` |
| 实名认证 | `PUT /user/auth/real-name` |
| 保存技能 | `POST /user/skill/save` |
| 保存可服务时间 | `POST /user/availability/save` |

### 4.5 我的排班

页面：

- 排班日历
- 排班列表
- 排班详情
- 确认排班

功能：

| 功能 | 后端接口 |
|------|----------|
| 排班详情 | `GET /schedule/{activityId}/detail` |
| 确认排班 | `POST /schedule/assignment/{assignmentId}/confirm` |

交互要求：

- 今日排班置顶。
- 排班状态使用颜色区分。
- 工作时间、区域、岗位、签到入口必须明显。

### 4.6 扫码/GPS 签到

页面：

- 扫码签到
- GPS 定位确认
- 签到结果
- 签到记录

功能：

| 功能 | 后端接口 |
|------|----------|
| 签到 | `POST /location/checkin` |
| 上报定位 | `POST /location/report` |
| 查询状态 | `GET /location/{userId}/status` |
| 生成二维码 | `POST /location/checkin/qrcode` |
| 签到记录 | `GET /location/checkins` |

交互流程：

```text
进入签到页
    ↓
扫描二维码
    ↓
获取当前位置
    ↓
提交 assignmentId + activityId + positionId + GPS
    ↓
展示签到结果
```

异常处理：

| 场景 | 处理 |
|------|------|
| 定位失败 | 提示开启定位权限 |
| 不在范围 | 提示当前位置不满足签到要求 |
| 重复签到 | 提示已签到 |
| 二维码失效 | 提示刷新二维码 |

### 4.7 实时定位

用途：

- 活动期间定时上报当前位置。
- 现场调度时用于附近人员推荐。

功能：

| 功能 | 后端接口 |
|------|----------|
| 定位上报 | `POST /location/report` |

规则：

- 只有活动进行中且用户有排班时才上报。
- 定位上报需要用户授权。
- 后台持续定位能力需要按微信小程序平台规范申请。

### 4.8 通知中心

页面：

- 通知列表
- 通知详情
- 标记已读

功能：

| 功能 | 后端接口 |
|------|----------|
| 通知列表 | `GET /message/receivers/{receiverId}/notices` |
| 标记已读 | `POST /message/notices/{id}/read` |

通知类型：

- 排班通知
- 调度通知
- 签到提醒
- 结算通知

### 4.9 我的收入

页面：

- 收入概览
- 结算单列表
- 结算详情
- 支付记录

功能：

| 功能 | 后端接口 |
|------|----------|
| 结算详情 | `GET /settlement/{id}/detail` |
| 我的结算 | `GET /settlement/users/{userId}/bills` |

> 当前后端结算查询接口还需对小程序侧补齐按用户查询能力。

### 4.10 我的

页面：

- 用户资料
- 技能标签
- 可服务时间
- 认证状态
- 设置
- 退出登录

## 7. API 封装规范

### 7.1 统一请求

```ts
interface ApiResult<T> {
  code: number;
  message: string;
  data: T;
}
```

统一封装：

- baseURL
- timeout
- Token header
- 错误提示
- 登录失效跳转

### 7.2 Token 处理

请求头：

```text
Authorization: Bearer ${token}
```

本地缓存：

```text
token
userInfo
```

### 7.3 错误处理

| 场景 | 处理 |
|------|------|
| 401 | 清除登录信息，跳转登录 |
| 403 | 提示无权限 |
| 业务失败 | 展示后端 message |
| 网络异常 | 提示网络异常 |
| 定位失败 | 引导开启授权 |

## 9. UI 规范

### 9.1 设计原则

- 移动端优先，操作路径短。
- 首页突出今日任务和签到入口。
- 排班、签到、调度通知必须清晰醒目。
- 表单字段少而明确，避免长表单堆叠。

### 9.2 状态颜色

| 状态 | 展示 |
|------|------|
| 正常/成功 | 绿色 |
| 待处理 | 蓝色 |
| 警告/迟到 | 黄色 |
| 异常/失败 | 红色 |
| 失效/已取消 | 灰色 |

### 9.3 常用组件

- 活动卡片
- 排班卡片
- 签到状态卡片
- 通知列表项
- 收入统计卡片
- 技能标签选择器
- 时间段选择器
- 定位授权提示

## 10. 权限与隐私

### 10.1 微信授权

需要申请：

- 用户信息授权
- 手机号授权
- 地理位置授权
- 扫码能力

### 10.2 隐私提示

定位上报必须明确告知用途：

- 用于现场签到校验
- 用于活动期间调度推荐
- 非活动期间不主动上报定位

### 10.3 数据安全

- 身份证等敏感信息不在列表页展示。
- 本地缓存不保存身份证号。
- 退出登录清理 Token 和用户缓存。
