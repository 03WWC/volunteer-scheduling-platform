# 志愿者智能调度平台 — 前端开发文档

---

## 1. 前端建设范围

本阶段优先建设 **管理后台 `frontend-admin`**，用于活动主办方、现场管理员完成活动配置、排班调度、现场监控、结算管理等后台操作。

微信小程序 `miniapp` 单独规划，本文只定义管理后台。

---

## 2. 技术栈

| 类型 | 选型 | 说明 |
|------|------|------|
| 框架 | Vue 3 | Composition API |
| 构建工具 | Vite | 快速开发与构建 |
| 语言 | TypeScript | 类型约束 |
| UI 组件库 | Element Plus | 后台管理界面 |
| 路由 | Vue Router | 页面路由与权限拦截 |
| 状态管理 | Pinia | 用户、权限、全局配置 |
| HTTP | Axios | 统一请求封装 |
| 图表 | ECharts | 统计看板、趋势图 |
| 地图 | 高德地图 JS API | 区域管理、实时定位 |
| 代码规范 | ESLint + Prettier | 统一格式 |
| 包管理 | pnpm | 推荐 |

## 4. 页面模块

### 4.1 登录页

|------|------|
| 登录 | 用户名/手机号 + 密码 |

| 路由跳转 | 登录后进入首页看板 |

### 4.2 首页看板

| 卡片 | 数据 |

| 已签到人数 | location-service |
| 缺岗数量 | dispatch-service |
| 待结算金额 | settlement-service |

### 4.3 活动管理

页面：

- 活动列表
- 新增/编辑活动
- 活动详情
- 区域管理
- 岗位管理

功能：

| 功能 | 后端接口 |
|------|----------|
| 创建活动 | `POST /activity/create` |
| 分页查询 | `GET /activity/page` |
| 修改活动 | `PUT /activity/update` |
| 删除活动 | `DELETE /activity/{id}` |
| 区域 CRUD | `/area/**` |
| 岗位 CRUD | `/position/**` |

### 4.4 志愿者管理

页面：

- 志愿者列表
- 志愿者详情
- 实名认证审核
- 技能标签管理
- 可服务时间查看

功能：

| 功能 | 后端接口 |
|------|----------|
| 志愿者列表 | `GET /user/list/volunteers` |
| 技能查询 | `GET /user/{id}/skills` |
| 用户注册 | `POST /user/register` |
| 实名认证 | `PUT /user/auth/real-name` |
| 技能保存 | `POST /user/skill/save` |
| 时间保存 | `POST /user/availability/save` |

### 4.5 排班管理

页面：

- 排班方案列表
- 排班详情
- 手动生成排班
- 发布排班
- 排班确认状态

功能：

| 功能 | 后端接口 |
|------|----------|
| 生成排班 | `POST /schedule/generate` |
| 排班详情 | `GET /schedule/{activityId}/detail` |
| 发布排班 | `POST /schedule/{planId}/publish` |
| 确认排班 | `POST /schedule/assignment/{assignmentId}/confirm` |

交互要求：

- 排班详情用表格展示：区域、岗位、人员、日期、开始时间、结束时间、状态。
- 发布排班前二次确认。
- 生成排班按钮需要 loading，避免重复点击。

### 4.6 现场调度

页面：

- 调度任务列表
- 调度结果详情
- 缺岗检测
- 附近人员推荐

功能：

| 功能 | 后端接口 |
|------|----------|
| 执行调度 | `POST /dispatch/execute` |
| 调度结果 | `GET /dispatch/{id}/result` |
| 缺岗检测 | `POST /dispatch/detect-shortage` |

交互要求：

- 缺岗检测需要选择活动，可选地图中心点和半径。
- 调度结果展示推荐人员、距离、匹配分、推荐状态。
- 调度状态用 Tag 展示：`FINISHED`、`PARTIAL`、`NO_CANDIDATE`。

### 4.7 签到定位

页面：

- 签到记录
- 实时人员状态
- 地图定位
- 附近人员查询

功能：

| 功能 | 后端接口 |
|------|----------|
| 上传定位 | `POST /location/report` |
| 查询附近人员 | `GET /location/nearby` |
| 查询人员状态 | `GET /location/{userId}/status` |
| 生成签到二维码 | `POST /location/checkin/qrcode` |
| 签到 | `POST /location/checkin` |
| 签到记录 | `GET /location/checkins` |

交互要求：

- 地图展示人员点位。
- 人员状态用颜色区分：在线、工作中、离线。
- 签到状态用表格展示。

### 4.8 结算管理

页面：

- 结算单列表
- 结算详情
- 生成结算单
- 确认结算
- 支付记录

功能：

| 功能 | 后端接口 |
|------|----------|
| 生成结算 | `POST /settlement/generate` |
| 确认结算 | `POST /settlement/{id}/confirm` |
| 支付 | `POST /settlement/{id}/pay` |

交互要求：

- 金额统一保留两位小数。
- 支付当前作为业务记录展示，不展示真实支付收银台。

### 4.9 消息通知

页面：

- 通知列表
- 通知详情
- 标记已读

功能：

| 功能 | 后端接口 |
|------|----------|
| 创建通知 | `POST /message/notices` |
| 接收人通知列表 | `GET /message/receivers/{receiverId}/notices` |

## 7. API 封装规范

### 7.1 请求基础配置

```ts
const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000
});
```

### 7.2 Token 透传

请求拦截器统一携带：

```ts
Authorization: Bearer ${token}
```

### 7.3 响应结构

后端统一返回：

```ts
interface ApiResult<T> {
  code: number;
  message: string;
  data: T;
}
```

前端只在 `code === 200` 时认为成功。

### 7.4 错误处理

| 场景 | 处理 |
|------|------|
| 401 | 清除 Token，跳转登录 |
| 403 | 提示无权限 |
| 业务错误 | 展示 `message` |
| 网络错误 | 提示网络异常 |
| 超时 | 提示请求超时 |

## 9. 权限设计

### 9.1 角色

| 角色 | 权限 |
|------|------|
| 平台管理员 | 全部权限 |
| 活动主办方 | 活动、排班、结算 |
| 现场管理员 | 签到、定位、调度 |
| 财务人员 | 结算、支付记录 |

### 9.2 权限控制

- 路由级权限：无权限不进入页面。
- 按钮级权限：新增、编辑、删除、发布、支付等按钮按权限展示。
- 数据级权限：后端最终控制，前端只做交互层限制。

## 10. UI 设计规范

### 10.1 页面风格

- 后台工具型界面，优先清晰、稳定、可扫描。
- 不做营销型大图首页。
- 表格、筛选、详情抽屉、弹窗是主要交互。
- 页面主色建议使用稳重蓝色，状态色使用 Element Plus 默认语义色。

### 10.2 列表页标准结构

```text
页面标题
筛选区
操作区
数据表格
分页
```

### 10.3 表单页规范

- 必填项必须有校验。
- 保存按钮有 loading。
- 关闭弹窗前检查未保存内容。
- 删除、发布、支付等危险操作必须二次确认。

### 10.4 状态展示

| 状态类型 | 展示 |
|----------|------|
| 成功 | 绿色 Tag |
| 处理中 | 蓝色 Tag |
| 警告 | 黄色 Tag |
| 失败/异常 | 红色 Tag |
| 已删除/禁用 | 灰色 Tag |

## 11. TypeScript 类型规范

### 11.1 命名

| 类型 | 规则 | 示例 |
|------|------|------|
| API 返回对象 | `XxxDTO` | `ActivityDTO` |
| 表单对象 | `XxxForm` | `ActivityForm` |
| 查询参数 | `XxxQuery` | `ActivityQuery` |
| 选项 | `XxxOption` | `StatusOption` |

### 11.2 禁止事项

- 禁止随意使用 `any`。
- 禁止在组件中直接拼接后端 URL。
- 禁止在页面中直接写大量业务常量。
- 禁止把接口返回结构和表单结构混用。

## 15. 当前依赖后端待补事项

前端开发时需要注意，以下后端能力仍可能继续变化：

| 后端能力 | 当前状态 | 前端处理 |
|----------|----------|----------|
| 登录认证 | 基础网关鉴权，登录接口未完整 | 前端先预留登录页和 Token 模型 |
| 自动排班算法 | 基础生成能力，算法待增强 | 页面先支持手动生成/展示 |
| 二维码签到 | 已完成 | 已支持生成、校验、过期和重复签到拦截 |
| 微信/短信通知 | 未完成 | 通知页面先展示站内通知 |
