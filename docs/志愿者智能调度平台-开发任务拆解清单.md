# 志愿者智能调度平台 — 开发任务拆解清单

---

## 第一阶段：基础架构搭建

### 任务 1：项目初始化

**负责人**：后端

**内容**：
- Spring Cloud Alibaba 搭建
- Nacos 注册中心
- Gateway 网关
- Docker 环境

**产出**：基础微服务框架

---

## 第二阶段：用户系统

### User-Service

**任务**：
- 用户注册
- 登录
- JWT 认证
- RBAC 权限

**接口**：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/user/login` | 登录 |
| POST | `/user/register` | 注册 |

---

## 第三阶段：活动服务

### Activity-Service

**任务**：
- 活动管理（创建/编辑/删除）
- 区域管理（地图区域绘制、保存区域坐标）
- 岗位管理（创建岗位、设置人数）

**数据库**：`activity_db`

---

## 第四阶段：报名服务

**任务**：

| 端 | 功能 |
|----|------|
| 志愿者端 | 浏览活动、报名岗位、提交时间 |
| 后台 | 审核报名 |

---

## 第五阶段：智能排班系统

### Schedule-Service

**开发**：排班算法

**任务**：
- 人员匹配
- 时间匹配
- 冲突检测

**接口**：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/schedule/generate` | 生成排班表 |

**输出**：排班表

---

## 第六阶段：实时定位系统

### Location-Service

**任务**：
- GPS 上传
- Redis GEO 存储
- 附近人员查询

**接口**：

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/location/upload` | 上传位置 |
| GET | `/location/nearby` | 查询附近人员 |

---

## 第七阶段：智能调度

### Dispatch-Service

**任务**：
- 缺员检测
- 自动推荐
- 调度通知

**流程**：
```
区域缺人 → 查询附近人员 → AI评分 → 发送任务
```

---

## 第八阶段：结算系统

### Settlement-Service

**任务**：
- 工时统计
- 工资计算
- 账单生成
- 支付接口

---

## 第九阶段：前端开发

### 管理后台

**页面**：
- 活动管理
- 地图编辑
- 排班管理
- 实时监控

**技术栈**：Vue3 + Element Plus + ECharts

### 移动端

**技术栈**：微信小程序

**功能**：
- 报名
- 排班查看
- 签到
- 调度接收

---

## 第十阶段：测试

### 压测

**工具**：JMeter

**测试场景**：
- 10万人报名
- GPS 百万数据
- 排班计算

---

## 第十一阶段：上线部署

**任务**：
- Docker 镜像构建
- Kubernetes 部署
- 日志系统（ELK）
- Prometheus 监控

---

## 最终项目模块结构

```
volunteer-platform
├── gateway                  # 网关
├── user-service             # 用户服务
├── activity-service         # 活动服务
├── schedule-service         # 排班服务
├── dispatch-service         # 调度服务
├── settlement-service       # 结算服务
├── location-service         # 定位服务
├── message-service          # 消息服务
├── AI-scheduler             # AI调度引擎
├── frontend-admin            # 管理后台（Vue3）
└── miniapp                   # 微信小程序
```
