# 阿里巴巴 Java 开发规范 — 核心编码规约

> 来源：《阿里巴巴Java开发手册》| 约束力：【强制】>【推荐】>【参考】

---

## 一、命名风格

| 规约 | 示例 |
|------|------|
| 类名 UpperCamelCase | `MarcoPolo`、`UserDO`、`XmlService` |
| 方法/变量 lowerCamelCase | `localValue`、`getHttpMessage()` |
| 常量全大写，下划线分隔 | `MAX_STOCK_COUNT` |
| 抽象类 Abstract/Base 开头 | `AbstractTranslator`、`BaseController` |
| 异常类 Exception 结尾 | `BusinessException` |
| 测试类 Test 结尾 | `UserServiceTest` |
| 包名全小写，单数形式 | `com.alibaba.open.util` |
| Service/DAO 接口 + Impl 实现 | `UserService` / `UserServiceImpl` |
| 枚举类 Enum 后缀，成员全大写 | `ProcessStatusEnum`、`SUCCESS` |
| Boolean 类型变量不加 is 前缀 | 反例：`Boolean isDeleted` → 框架序列化问题 |

## 二、常量定义

**【强制】** 不允许任何魔法值直接出现在代码中。

**【强制】** Long 初始赋值用大写的 `L`，不用小写 `l`（易混淆数字 1）。

**【推荐】** 常量按功能分类维护，不建大而全的常量类。

```java
// 正例：按功能分类
public class CacheConsts { ... }
public class ConfigConsts { ... }

// 反例：魔法值
String key = "Id#taobao_" + tradeId;  // ❌
```

## 三、POJO 规约

| 规约 | 说明 |
|------|------|
| 【强制】POJO 类属性必须用包装数据类型 | `Long id`，不用 `long id`（防 NPE） |
| 【强制】POJO 类不要设定任何属性默认值 | 由使用者显式赋值 |
| 【强制】构造方法禁止加入业务逻辑 | 初始化逻辑放 `init()` 方法 |
| 【强制】POJO 类必须写 `toString()` | 方便异常时排查问题 |

---

## 四、集合处理

| 规约 | 说明 |
|------|------|
| 【强制】判空用 `isEmpty()`，不用 `size() == 0` | 可读性更好 |
| 【强制】数组转集合用 `toArray(T[] array)` | 传入长度 0 的空数组 |
| 【强制】`Arrays.asList()` 返回的集合不能 add/remove/clear | 会抛异常 |
| 【强制】foreach 中不能 remove/add 元素 | 使用 Iterator 方式 |

---

## 五、并发处理

| 规约 | 说明 |
|------|------|
| 【强制】线程必须通过线程池创建 | 不允许自行 `new Thread()` |
| 【强制】线程池不允许用 `Executors` 创建 | 用 `ThreadPoolExecutor`（防 OOM） |
| 【强制】`SimpleDateFormat` 是线程不安全 | 用 `DateTimeFormatter`（JDK8） |
| 【强制】高并发避免用"等于"判断作为终止条件 | 用大于/小于区间判断 |

---

## 六、异常与日志

| 规约 | 说明 |
|------|------|
| 【强制】生产禁用 `System.out` / `e.printStackTrace()` | 应用日志框架 |
| 【强制】异常捕获后要处理 | 不要空 catch |
| 【推荐】日志至少保存 15 天 | — |
