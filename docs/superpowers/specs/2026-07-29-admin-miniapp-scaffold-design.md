# 管理后台与小程序基础工程设计

## 目标

在现有志愿者智能调度平台后端基础上，同时建立可运行的管理后台和微信小程序基础工程。首期重点是统一工程结构、视觉语言、路由、状态管理、请求封装和主要业务页面，使后续能够按模块直接接入真实接口。

## 范围

### 管理后台

- 技术栈：Vue 3、Vite、TypeScript、Vue Router、Pinia、Axios、Element Plus。
- 默认通过网关 `http://localhost:8080` 访问后端。
- 提供登录页、后台布局、仪表盘，以及活动、志愿者、排班、调度、签到、结算、消息等业务入口。
- 页面采用适合运营人员高频操作的紧凑布局：侧边导航、顶部状态区、筛选工具栏、数据表格和明确的操作按钮。

### 小程序

- 技术栈：uni-app、Vue 3、TypeScript、Pinia。
- 默认通过网关 `http://localhost:8080` 访问后端，允许通过环境变量切换。
- 提供微信登录、首页、活动、排班、扫码签到、消息、收入和个人中心页面。
- TabBar 固定为首页、活动、排班、消息、我的，扫码签到作为首页和排班详情中的主操作。

## 架构

两个客户端分别位于 `frontend-admin/` 和 `miniapp/`，互不共享构建依赖，避免发布流程耦合。每个客户端内部按 `api`、`stores`、`router/pages`、`styles`、`types` 分层；所有服务端返回值通过统一请求层解析，业务页面不直接处理 Axios 或 `uni.request` 的底层响应。

## 数据流

1. 页面触发查询或提交。
2. 对应业务 API 模块调用统一请求客户端。
3. 请求客户端添加登录凭证并解析 `ApiResult<T>`。
4. 成功时返回业务数据，失败时统一显示后端错误信息。
5. 登录态由 Pinia 保存，并同步到本地存储。

## 错误处理

- 网络失败、超时和非成功业务码统一转换为可展示的错误信息。
- 登录失效时清理本地登录态并跳转登录页。
- 页面保留加载、空数据和失败状态，避免操作无反馈。

## 验证

- 请求结果解析和登录状态逻辑使用 Vitest 验证。
- 两个工程执行 TypeScript 类型检查和生产构建。
- 管理后台启动后使用桌面与移动视口检查布局。
- 小程序至少完成 H5 构建验证，微信开发者工具联调留给真实 AppID 环境。
