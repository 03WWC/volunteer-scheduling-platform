# 统一技能字典设计

## 目标

将岗位技能要求和志愿者技能标签统一为固定编码，界面只要求用户选择中文名称，避免自由输入造成自动排班无法匹配。

## 范围

1. 后台岗位新建/编辑使用中文技能下拉；后台新增志愿者沿用同一份技能字典。
2. 小程序“我的 - 技能标签”使用中文技能和中文等级选择器，保存时自动提交标准编码。
3. 自动排班匹配技能编码时忽略首尾空格和大小写，兼容已有手工录入数据。

不新增数据库表，不修改现有接口字段，不迁移或删除历史技能数据。

## 技能字典

岗位可选择“不限技能”，志愿者个人技能不提供该选项。

| 编码 | 中文名称 | 使用范围 |
| --- | --- | --- |
| `NONE` | 不限技能 | 岗位 |
| `GUIDE` | 秩序引导 | 岗位、志愿者 |
| `REGISTRATION` | 信息登记 | 岗位、志愿者 |
| `MATERIAL` | 物资搬运 | 岗位、志愿者 |
| `CLEANING` | 环境清洁 | 岗位、志愿者 |
| `TRAFFIC` | 交通协助 | 岗位、志愿者 |
| `SECURITY` | 安全巡查 | 岗位、志愿者 |
| `MEDICAL` | 医疗急救 | 岗位、志愿者 |
| `EMERGENCY` | 应急救援 | 岗位、志愿者 |
| `EXPLANATION` | 活动讲解 | 岗位、志愿者 |
| `PHOTOGRAPHY` | 摄影宣传 | 岗位、志愿者 |

技能等级固定为 `BEGINNER`（基础）、`INTERMEDIATE`（熟练）、`EXPERT`（专家）。

## 数据流

后台岗位和志愿者表单、小程序技能表单都显示中文名称，但接口继续提交 `skillRequirement` 或 `skillCode` 英文编码。`skillName` 由所选编码自动带出。排班服务对岗位编码和志愿者编码执行 `trim` 后进行不区分大小写的比较。

## 兼容与异常处理

- 旧岗位的空值、`无`、`不限`、`不限技能`、`ANY`、`NONE` 继续视为不限技能。
- 未收录在字典中的历史编码仍按原值显示，编辑时可重新选择标准技能。
- 获取不到志愿者技能时维持当前行为：该志愿者不满足有技能要求的岗位。

## 验证

- 字典单元测试覆盖编码规范化、中文名称映射和岗位/志愿者选项边界。
- 排班服务回归测试证明岗位与志愿者编码仅大小写或空格不同时仍可匹配。
- 后台执行测试和生产构建；小程序执行测试和微信小程序生产构建；排班模块执行 Maven 测试。
