# 后台多管理员与权限树实施计划

## 目标

把后台管理员从配置文件单账号升级为数据库账号体系，支持多个后台人员按角色获得不同权限。第一阶段先完成登录权限闭环：管理员从数据库登录，接口返回角色和权限编码，前端根据权限显示菜单。

## 权限模型

- 管理员账号：后台登录主体，保存在 `admin_user`。
- 角色：权限集合模板，保存在 `admin_role`。
- 权限：按模块和操作拆分的权限树，保存在 `admin_permission`。
- 账号角色关系：`admin_user_role`。
- 角色权限关系：`admin_role_permission`。

## 默认角色

- `SUPER_ADMIN`：系统超级管理员，拥有全部权限。
- `ACTIVITY_MANAGER`：活动、区域、岗位管理。
- `SIGNUP_REVIEWER`：报名审核。
- `SCHEDULE_MANAGER`：排班和智能调度。
- `CHECKIN_MANAGER`：签到记录和签到码。
- `NOTICE_MANAGER`：通知中心。
- `VIEWER`：只读查看。

## 第一阶段交付

1. 新增 RBAC 表和初始化 SQL。
2. 后台登录优先查询数据库管理员，失败时兼容旧配置管理员。
3. 登录返回 `roles` 与 `permissions`。
4. 前端保存权限并按菜单权限过滤。

## 后续阶段

1. 后台账号管理页面：新增、停用、重置密码、分配角色。
2. 角色权限树页面：勾选权限树并保存。
3. 后端接口级权限校验：从网关透传用户后，在服务侧校验关键操作。
