## 2. 微服务拆分设计

### 2.1 活动服务 Activity-Service

**职责**：
- 活动创建
- 区域管理
- 岗位管理

**数据库**：`activity_db`

**核心表结构**：

**activity（活动表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| name | varchar | 活动名称 |
| start_time | datetime | 开始时间 |
| end_time | datetime | 结束时间 |
| location | varchar | 地点 |
| status | int | 状态 |

**activity_area（区域表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| activity_id | bigint | 活动ID |
| area_name | varchar | 区域名称 |
| polygon | text | 区域多边形坐标 |

**position（岗位表）**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键 |
| area_id | bigint | 区域ID |
| name | varchar | 岗位名称 |
| require_count | int | 需求人数 |

---

### 2.2 排班服务 Schedule-Service

**职责**：
- 自动排班
- 排班发布
- 冲突检测

**核心算法：约束满足问题（CSP）**

```
输入：
  ├── 人员集合
  ├── 岗位集合
  └── 时间集合

约束：
  ├── 时间不能冲突
  ├── 距离满足
  ├── 技能匹配
  └── 人数满足

技术：Java + OR-Tools
```

---

### 2.3 调度服务 Dispatch-Service

**职责**：实时调度

**架构流程**：

```
GPS数据
    ↓
定位服务
    ↓
Redis GEO
    ↓
附近人员查询
    ↓
AI 推荐
    ↓
MQ 通知
```

**Redis GEO 使用示例**：

```bash
GEOADD volunteer_location 116.40 39.90 user1001
# 查询附近500米人员
GEORADIUS volunteer_location 116.40 39.90 500 m
```

---

### 2.4 结算服务 Settlement-Service

**职责**：
- 工资计算
- 补贴
- 对账

**流程**：

```
签到成功 → 生成工时 → 计算金额 → 生成账单 → 支付
```

## 3. AI 智能排班设计

### 输入

| 维度 | 内容 |
|------|------|
| 人员 | 技能、历史评分、位置、空闲时间 |
| 岗位 | 技能要求、人数、时间 |

### 输出

最优排班方案

### 算法设计

**第一阶段 — 规则过滤**：
- 按技能要求、时间窗口硬过滤

**第二阶段 — AI 优化**：

目标函数：

| 最大化 | 降低 |
|--------|------|
| 人员匹配度 | 空岗率 |
| 距离最短 | 冲突率 |
| 满意度最高 | — |

## 4. Redis 设计

### 热点数据

| Key | 用途 |
|-----|------|
| `activity:{id}:status` | 活动实时状态 |
| `geo:activity:{id}` | 人员定位（GEO） |
| `sign:{activityId}:{userId}` | 签到状态 |
| `schedule_lock` | 排班分布式锁 |

## 5. MQ 设计

采用 **RocketMQ**。

### Topic 设计

| Topic | 用途 | 消费者 |
|-------|------|--------|
| `schedule.publish.topic` | 排班发布 | APP通知服务、实时调度 |
| `dispatch.event.topic` | 调度事件 | 调度处理服务 |

**消息格式示例**：

```json
{
  "userId": "1001",
  "areaId": "A01",
  "task": "请前往舞台区支援"
}
```

## 7. 高并发设计

### 7.1 活动报名

**问题**：万人同时报名

**方案**：
```
Redis 缓存库存（报名人数: 10000）
    ↓
Redis 原子操作 DECR
    ↓
MQ 异步写数据库
```

### 7.2 定位数据

**问题**：10万人实时GPS

**方案**：
```
APP → MQ → 定位服务 → Redis GEO（批量更新）
```
